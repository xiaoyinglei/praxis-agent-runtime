# Praxis 终端交互改版

日期：2026-10-20
状态：用户已确认方案，已实现并通过定向验证。

## 目标与范围

面向普通用户，让终端像一个可靠的工作助手：读得清回答，看得到操作，知道当前在等什么，遇到问题能判断是否需要处理。

本次范围是现有 prompt_toolkit 终端的呈现与交互。复用 canonical 事件与 AgentResult；不改变执行循环、权限边界、工具定义、模型请求或失败恢复策略，不重启历史会话，不新增模型调用来生成状态说明。

备选方案是常驻任务侧栏或仅更换配色。用户选择接近 Claude Code 的顺序对话：操作内联，长内容折叠，输入区稳定，细节按需查看。

参考公开交互机制：https://code.claude.com/docs/en/interactive-mode 。借鉴交互与信息层级，保留 Praxis 名称；不宣称获取或复制 Claude Code 的非公开实现。

## 默认布局

```text
  ✳ Praxis  ·  项目名称

❯ 根据数据生成一份报告

● 我会先核对数据，再生成报告并检查结果。

● 读取文件  data/sales.xlsx
  ⎿ 已读取 2 个工作表

● 执行命令  生成报告
  ⎿ 报告文件已写入

✳ 正在检查生成结果… · 24 秒

────────────────────────────────────────────────
❯ 补充要求或输入下一条消息…
────────────────────────────────────────────────
  Ctrl+C 停止 · Ctrl+O 详情 · Ctrl+J 换行
```

示例文案来自假设的真实事件；界面不能从工具名称推测业务结果。例如没有结构化工作表数量时，只能显示“读取完成”。运行中事件只有工具名称时，标题只显示“执行命令”等名称。当前 canonical 工具开始事件不携带完整参数，不为美化标题新增协议或读取数据库；实际命令、路径与参数在可信结果或 AgentResult.tool_calls 可得后按 tool_call_id 补齐。仍然缺失就明确标为“参数未提供”，不能从助手文本推测。可得的命令和参数统一使用安全、有限长度的预览。

默认沿对话顺序呈现每项操作的一行标题和最多两行结果预览，不再将所有操作套在默认展开的“执行记录”大组内。每项操作的长输出、参数、错误原文放在详情。长连续操作最多显示最近 5 项，其余以“另有 N 项操作 · Ctrl+O”折叠；助手回答与需要处理的问题不会被折叠。完成后的普通操作仍保持紧凑预览，不强制所有历史内容消失。

顶部欢迎区在初次进入展示；inline 模式进入对话后收起固定欢迎区，避免它随每次重绘占三行。fullscreen 模式保留一行项目标识。使用终端默认背景和前景，一种低饱和强调色；弱信息用暗色，警告用黄色，需要处理的失败用红色。文字和符号也表达状态，不能只靠颜色。兼容浅色、深色和 NO_COLOR。

输入区上下只用细线，不增加常驻侧栏和仪表盘。空闲时一行帮助；执行时一行当前状态。模型、请求参数、上下文容量、token 用量不占默认界面的两行常驻状态栏；保留既有查询命令，Ctrl+O 详情里也能查到。本次不新增主题选择器或配置系统。

## 状态与事实来源

界面状态是已有事件的投影，不能依靠错误文本开头、颜色符号或助手措辞推断生命周期。以 turn_id、item_id 和事件序列标识归属并去重；详细原文与投影分开保留，折叠不会丢数据。

| 用户看到的状态 | 事实来源与边界 |
| --- | --- |
| 等待模型响应 | 请求已开始但尚无输出；不能标成思考中 |
| 思考中 | 已收到 reasoning 增量；只显示状态，不展示内部推理原文 |
| 正在回答 | assistant 文本增量 |
| 正在读取文件 / 执行命令 | 对应工具或命令 item_started；并行操作显示最近活动与其他进行中数量 |
| 操作失败，继续处理中 | 工具失败但本轮仍活跃；不宣称已经开始重试 |
| 正在恢复 | 已收到明确 RECOVERY 事件；不能仅凭工具失败显示正在重试 |
| 等待你的确认 / 回答 | AgentPause 与 HUMAN_INPUT_REQUIRED |
| 正在停止 | 取消已请求但清理尚未结束 |
| 已停止 / 未完成 | 已确认取消、失败或结果未知；保留已发生的修改与未知结果提示 |
| 本轮已结束 | AgentResult done；不等于业务验收通过 |

工具调用返回成功不一定表示命令进程结束。run_command / manage_command 的结构化结果若为 status=running，则继续显示“命令运行中”，按 session_id 关联后续状态；只有同一 session 的明确终态才能标记完成。exit_code 非零、cancelled 与 outcome_unknown 分别显示失败、已取消与结果未确认。对结果未知的进程不能宣称已停止；整个 Turn 已结束也不能覆盖仍运行的命令状态。session_id 在详情可查，默认行不展示内部 ID。

动态行只显示真实经过时间，不估算百分比或剩余时间。运行中每秒刷新该行；空闲时停止定时重绘，保留原生选取与滚动行为。没有新事件时，基于单调时钟显示“等待响应 · 距上次活动 N 秒”，不因沉默就判定模型失败或进程死亡，也不自动触发重试。连续 reasoning 增量是活动信号，会更新最近活动时间。

计划以 ITEM_COMPLETED + TurnItemKind.PLAN 中的结构化 data.plan 快照为主，兼容已有 PLAN_UPDATED，按 turn/revision 去重后展示简短清单；不固定占据侧栏。不为每项任务虚构计划或进度。模型主动输出的简短工作说明按普通助手消息展示。

## 失败、恢复与交付

一次失败只保留一处主记录，原文可展开。已知错误代码映射为简短、可行动的通用说明；未知错误保留有限长度的安全原文，不伪造原因。标准工具与第三方 MCP 都有后备名称和预览，不能只支持内置工具。

```text
● 执行命令  生成报告
  ⎿ 这一步失败了，正在继续处理              Ctrl+O 详情

✳ 正在恢复：重试模型请求…
```

上述恢复行仅在对应 RECOVERY 事件到达时出现。网络瞬时错误或一次工具失败不能将整个任务染成红色。恢复成功的操作保留历史失败事实；只有存在明确关联的重试及成功结果才能标记“已恢复”，不能以任意后续成功覆盖前一次失败。

需要用户处理时，说明发生了什么、哪一步停止、可以选什么。例如系统拒绝读取时展示“无法读取这份文件，请选择可访问的副本”，详情保留原错误。没有确认保留了哪些结果时，不承诺“数据已保留”。权限确认继续使用运行时给定选项和授权范围，简化措辞但不放宽授权；拒绝、取消与补充说明仍可用。

交付摘要使用 AgentResult.files、status、validation_status、validation_scope。files 仅表示结果携带的文件引用，不能单凭路径就标记文件存在、可打开或内容正确。只有验证 passed 才展示“已验证”，并同时写明 validation_scope；not_evaluated 展示“未运行验收”，failed 明确“验收未通过”。任何“已检查排版”都必须来自确实覆盖排版的验证范围。展示已有文件路径，支持的终端可用安全 OSC 8 链接；不新增文件打开权限。助手自己的完成声明不能改变这些状态。

## 交互与兼容

- Enter 发送，Ctrl+J / 已支持的多行按键换行；粘贴、文件输入与历史检索保持既有语义。
- Ctrl+O 切换普通对话和详细记录；再次按下返回，保存输入草稿、光标和对话滚动位置。详情里保留工具参数、长输出、原始错误、请求设置与使用量。
- Ctrl+C 继续现有复制、清空、停止的上下文优先级。Esc 先关闭补全、菜单或详情，再按当前场景处理审批；普通执行时可停止当前操作。取消必须等待真实清理结果，不谎报已经停止。
- 执行时可继续编辑与补充，沿用现有 steer 与 input receipt。发送后明确区分“已接收，等待应用”和“已应用”；不能把清空输入框视作已应用。
- 上下键、Tab、Enter 可完成审批和菜单操作。快捷键提示随场景改变，不能依赖鼠标或颜色。
- 兼容 macOS、Linux SSH、80×24 与窄屏、中文双宽字符、长路径、resize、NO_COLOR、非 TTY 和 native scrollback。NO_COLOR 关闭颜色，不关闭必要的终端输入协议。
- 原生选择与复制优先；默认不启用鼠标捕获。退出或异常时恢复终端、stdout、stderr 与日志处理器。窗口很矮时缩减装饰与预览，保留输入、当前状态和审批操作。

## 代码边界

- terminal_ui.py：保留式对话、操作预览、详情视图及结构化状态投影。业务状态以事件字段为依据，移除以展示字符串推断工具成功/失败的耦合。
- terminal_app.py：布局、输入、焦点、快捷键、运行时刷新与终端恢复。复用 prompt_toolkit，不引入 TUI 框架。
- terminal_render.py：复用安全文本、显示宽度、有限预览和既有格式器；保留非交互 CLI 的可读输出，避免 UI 修改破坏脚本使用。
- cli.py：把最终 AgentResult 和接收回执传给 UI，并接通取消过程的真实结果。当前提前调用 display.interrupted() 的路径改为先显示“正在停止”，保留 abort 返回结果并传递 event_sink，待确认终态后才显示已取消；结果未知如实保留。不更改运行时/SDK 语义。
- AgentResult 和 streaming/events.py 作为现有契约输入，本次不新增通用验证引擎、恢复管理器、持久化协议或事件总线。

## 验收与测试

仅运行变更相关的终端渲染、UI 模式、输入、steering 与审批测试，具体选择随改动确定；不因样式调整全量重跑仓库。

关键行为使用已有事件回放：正常工具调用、并发操作、命令持续输出、工具成功返回但进程仍运行、同 session 终态、工具失败但本轮继续、明确恢复事件、审批暂停、补充应用、取消待清理、结果未知、最终验收通过/失败/未执行。覆盖 canonical PLAN 快照及兼容事件去重、运行中仅有工具名和最终参数补齐。断言状态真实性、错误只出现一次、详情数据未丢失、草稿和焦点不变。

已有固定两行技术状态栏的测试应调整为“普通视图简洁，详情可读取相同权威值”，不能删掉用量未知/不完整、缓存、请求设置归属等断言。

使用 Vt100_Output 和 pipe input 在 80×24、窄屏、resize、NO_COLOR、inline/fullscreen 下检查最终屏幕与键盘操作；记录少量可审阅的终端画面。测试终端安全转义与长输出边界，不打印未经清理的外部 ANSI 控制序列。

真实 smoke 使用一个无敏感数据的小任务，覆盖工具操作、用户中断及交付摘要；沿用已配置模型，不另装模型。报告任务验收只证明实际检查范围，不宣称版面/事实全面验证。没有真实恢复场景时使用确定性事件回放覆盖，不制造有副作用的失败来演示。Git 提交与服务器部署在 UI 代码完成并获授权后进行；本次已授权的前序 CI 修订单独合并。

## 实施时发现的取消缺口

真实模型与原生命令的 Ctrl+C 验证发现，原串行 ToolExecutor 路径没有接入既有 cancellation_sink，且工具阶段取消后 Turn 仍保持 running。为兑现本方案的停止状态契约，实施包含三处必要接线：串行执行复用现有取消结果提交回调；工具批次取消后请求取消并安全暂停；CLI 等待真实 abort 结果。未更改权限、远端未知结果处理或 abort 的 running/unknown 拒绝条件。串行、并行和远端未知结果都有定向回归，真实命令中断已验证。
